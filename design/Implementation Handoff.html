Frontend Spec

CSS tokens, HTML patterns, and a rendering matrix for implementing the pgstack design system in plain Django templates extending base.html. No React, no Vue, no build step on the frontend.

Django 5 Channels 4 Daphne 4 PostgreSQL 16 No JS framework Server-rendered templates
01

CSS custom properties

Copy into static/css/base.css

All design tokens are defined as CSS custom properties on :root. Dark mode overrides live under [data-theme="dark"] — set the attribute on <html> via a user preference cookie.

static/css/base.css CSS 
/* ── Surface ───────────────────────────────── */
:root {
  --bg:       #f3efe6;  /* page background */
  --bg-2:     #ebe6da;  /* elevated surface, table headers */
  --paper:    #faf7f0;  /* cards, nav, inputs */

  /* ── Text ──────────────────────────────────── */
  --ink:      #14181d;  /* primary text */
  --ink-2:    #2a2f37;  /* secondary text */
  --muted:    #6b6f78;  /* placeholders, labels, captions */

  /* ── Borders ───────────────────────────────── */
  --rule:     #d9d3c4;  /* dividers, row separators */
  --rule-2:   #c8c1ae;  /* card borders, input borders */

  /* ── Accent — Postgres blue ────────────────── */
  --pg:       #2f6fb5;  /* links, focus rings, active nav */
  --pg-deep:  #1f4d80;  /* text on pg-soft surfaces */
  --pg-soft:  #e6eef8;  /* tag backgrounds, info banners */

  /* ── Semantic ──────────────────────────────── */
  --green:    #3d7a4a;  /* done, success */
  --amber:    #b97d2a;  /* processing, warning */
  --red:      #b14b3c;  /* overdue, error, failed */

  /* ── Typography ────────────────────────────── */
  --sans:  "Geist", ui-sans-serif, system-ui, sans-serif;
  --mono:  "Geist Mono", ui-monospace, "SF Mono", Menlo, monospace;
  --serif: "Instrument Serif", Georgia, serif; /* editorial only */

  /* ── Shadows ───────────────────────────────── */
  --shadow-sm:   0 1px 2px rgba(20,24,29,0.08);
  --shadow-md:   0 4px 12px rgba(20,24,29,0.12);
  --shadow-card: 0 1px 0 rgba(20,24,29,0.02), 0 24px 60px -40px rgba(20,24,29,0.18);
  --focus-ring:  0 0 0 3px rgba(47,111,181,0.18);
}

04

Global nav — base.html

Django template · no JS

The nav shell lives in templates/base.html and is extended by every page template. Active state is detected via request.resolver_match.app_name — set app_name in each app's urls.py.

templates/base.html HTML + Django 
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8"/>
  <meta name="viewport" content="width=device-width, initial-scale=1"/>
  <title>{% block title %}pgstack{% endblock %}</title>
  <link rel="stylesheet" href="{% static 'css/base.css' %}"/>
  {% block extra_head %}{% endblock %}
</head>
<body>

<nav class="site-nav" aria-label="Main navigation">
  <div class="site-nav__inner">

    <!-- Wordmark -->
    <a href="{% url 'todos:index' %}" class="site-nav__brand">
      <span class="brand-mark" aria-hidden="true">pg</span>
      <span class="brand-name">pgstack</span>
      <span class="brand-version" aria-hidden="true">v0.1</span>
    </a>

    <!-- Page links — active class via app_name -->
    <ul class="site-nav__links" role="list">
      {% with app=request.resolver_match.app_name %}
      <li><a href="{% url 'todos:index' %}"
             class="site-nav__link {% if app == 'todos' %}is-active{% endif %}">
        Todos</a></li>
      <li><a href="{% url 'search:index' %}"
             class="site-nav__link {% if app == 'search' %}is-active{% endif %}">
        Search</a></li>
      <li><a href="{% url 'users:search' %}"
             class="site-nav__link {% if app == 'users' %}is-active{% endif %}">
        Users</a></li>
      <li><a href="{% url 'dashboard:index' %}"
             class="site-nav__link {% if app == 'dashboard' %}is-active{% endif %}">
        Dashboard</a></li>
      <li><a href="{% url 'queue:index' %}"
             class="site-nav__link {% if app == 'queue' %}is-active{% endif %}">
        Queue</a></li>
      <li><a href="{% url 'settings:index' %}"
             class="site-nav__link {% if app == 'settings' %}is-active{% endif %}">
        Settings</a></li>
      {% endwith %}
    </ul>

    <!-- Auth area -->
    <div class="site-nav__auth">
      {% if user.is_authenticated %}
        <span class="site-nav__avatar" aria-hidden="true">
          {{ user.username|slice:":2"|upper }}
        </span>
        <span class="site-nav__username">{{ user.username }}</span>
        <form method="post" action="{% url 'auth:logout' %}">
          {% csrf_token %}
          <button type="submit" class="btn btn--sm">Log out</button>
        </form>
      {% else %}
        <a href="{% url 'auth:login' %}" class="site-nav__link">Log in</a>
        <a href="{% url 'auth:register' %}" class="btn btn--primary btn--sm">Register</a>
      {% endif %}
    </div>

  </div>
</nav>

<!-- Django messages — rendered once per page -->
{% if messages %}
<div class="messages-container" role="status" aria-live="polite">
  {% for message in messages %}
  <div class="msg-banner msg-banner--{{ message.tags }}">
    <span class="msg-banner__icon" aria-hidden="true"></span>
    <span class="msg-banner__text">{{ message }}</span>
  </div>
  {% endfor %}
</div>
{% endif %}

<main class="page-content">
  {% block content %}{% endblock %}
</main>

{% block extra_js %}{% endblock %}
</body></html>

08

Rendering matrix

Server-rendered vs client-only

Every page is server-rendered via Django views and templates. The single exception is the live todo list, which uses a WebSocket for real-time updates — all other interactivity is standard HTTP form posts.

Template / ComponentRouteRenderingNotes
Landing page / Server Static — redirects to login if unauthenticated
Log in /auth/login/ Server django.contrib.auth.views.LoginView
Register /auth/signup/ Server Custom view using extended UserCreationForm
Todo list (index) /todos/ Server + WS Initial render is server-side; a small inline <script> opens a WebSocket and prepends new todos via insertAdjacentHTML on LISTEN/NOTIFY push. Only page with any client JS.
Search todos /search/ Server GET form — results rendered server-side with ts_headline
Dashboard /dashboard/ Server Reads todo_stats materialized view — no polling, no JS
Queue monitor /queue/ Server Simple queryset — page must be manually refreshed to see updates
Find users /users/search/ Server GET form — username__icontains query
Public todo list /users/<username>/todos/ Server Scoped search via GET; returns 403 if profile is private
Settings /settings/ Server POST form; success shown via messages.SUCCESS
Nav shell all pages Server {% if user.is_authenticated %} controls auth area; active link via app_name
Status / job badges all pages Server Pure CSS — .badge--{{ status|lower }} from template tag
FTS highlight search pages Server SearchHeadline annotation → {{ headline|safe }} → CSS on <b>
WebSocket (live todos) /ws/todos/ Client ~20 lines of vanilla JS in {% block extra_js %} on todos/index.html only. No framework. Opens connection, handles onmessage, calls insertAdjacentHTML.
!
WebSocket scope — the Channels consumer at /ws/todos/ is scoped to the authenticated user's own todos. It does not broadcast across users. The ASGI worker (Daphne) must be running; the standard runserver does not support WebSockets.
templates/todos/index.html — WebSocket snippet (the only client JS)JS
{% block extra_js %}
<script>
// Vanilla JS — no framework. Opens WS, prepends new todos on notify.
(function () {
  const list   = document.getElementById('todo-list');
  const scheme = location.protocol === 'https:' ? 'wss' : 'ws';
  const ws     = new WebSocket(`${scheme}://${location.host}/ws/todos/`);

  ws.onmessage = function (e) {
    const todo = JSON.parse(e.data);
    // Build a minimal row; full render is still server-side on refresh.
    const html = `
      <li class="todo-row todo-row--new" id="todo-${todo.id}">
        <span class="todo-row__title">${todo.title}</span>
        <span class="badge badge--pending">Pending</span>
      </li>`;
    list.insertAdjacentHTML('afterbegin', html);
  };
}());
</script>
{% endblock %}
